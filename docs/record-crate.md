# 레코드 복제 · 상자(크레이트) 설계 노트

상태: **미구현 설계 노트** · 2026-10-22 논의 기준
이 문서가 `record-break.md`(파손 대안)를 대체하는 실제 방향이다.

## 0. 한 줄 요약

노치의 레코드를 **그냥 클릭하면 상자로 빼서 담고(복제)**, **Cmd를 누른 채 클릭하면
(Cmd를 클릭 전에 누르거나 클릭 중에 눌러도)** 노치 레코드와 상자 레코드를
**맞바꾼다**. 상자에 모인 레코드는 그대로 **플레이리스트**가 된다. 상자에서 레코드를
위로 꺼내면 노치에 다시 꽂혀 재생되고, 아래로 떨어뜨리면 **깨지지 않고 쏙 빠져나간다**.
원본 레코드는 노치에 그대로 남고 재생도 계속된다.

상자는 로컬 메타데이터와 아트워크로 렌더링되므로 **Music이 꺼져 있어도 보인다**.
곡의 정체성(제목·아티스트·앨범·persistent ID·아트워크)은 복제 시점에 항상 알 수 있고,
**재삽입 재생만 곡 소스에 따라 제한된다**(6장). 데스크탑 장식 용도로는 이 제한이
영향을 주지 않는다.

## 1. 개념

- **노치 = 턴테이블.** 지금 재생 중인 트랙이 레코드로 꽂혀 있다.
- **그냥 클릭 = 빼기(복제).** 원본을 옮기는 게 아니라, 같은 레코드를 한 장 더 찍어
  상자에 넣는다. 원본은 노치에서 계속 재생된다.
- **Cmd+클릭 = 바꾸기(교환).** 노치 레코드와 상자 레코드를 맞바꾼다. 같은 쌍을 다시
  Cmd+클릭하면 원래대로 돌아가는 토글이다.
- **상자 = 크레이트 = 플레이리스트.** 레코드를 모으는 행위가 곧 플레이리스트를
  만드는 행위다. 상자를 여러 개 두면 여러 플레이리스트가 된다.
- **다시 꽂기 = 재생.** 상자에서 레코드를 꺼내 노치에 넣으면 그 트랙이 재생된다.
- **아래로 드롭 = 꺼내기.** 상자에서 레코드를 아래로 떨어뜨리면 소리 없이 빠져나간다.
  파손 연출은 없다.

핵심은 **파괴가 아니라 수집**이다. "좋아하는 노래를 한 장 더 찍어 모아 둔다"가
이 기능의 정서다.

## 2. 확정된 원칙

- **원본 유지.** Cmd+클릭은 복제만 한다. 노치의 레코드와 재생 상태는 바뀌지 않는다.
- **상자는 로컬 우선.** Music의 `disliked`, 플레이리스트 삭제 같은 사용자 데이터는
  건드리지 않는다. 상자는 Umak이 로컬에 저장한다.
- **깨지지 않는다.** 아래로 드롭하면 짧게 미끄러져 사라지는 연출만 쓴다.
- **기존 제스처는 최소 변경.** 새 의미는 클릭과 Cmd+클릭에만 얹고, 드래그/스크롤의
  기존 의미는 유지한다. 단, 본체 클릭을 "빼기"로 쓰면 기존 "닫기"를 다른 제스처로
  옮긴다(9장).
- **플레이리스트 내보내기는 별도 동작.** 사용자가 명시적으로 요청할 때만 Music에
  새 플레이리스트를 만든다(추가 전용, 삭제 없음).

## 3. 제스처 지도

| 입력 | 위치 | 동작 |
| --- | --- | --- |
| 그냥 클릭 | 노치 레코드 본체 | 현재 트랙을 상자로 빼기(복제). 원본 유지, 재생 계속 |
| 그냥 클릭 | 노치 레코드 레이블 | 기존대로 재생/일시정지 (유지) |
| 그냥 클릭 | 상자 안의 레코드 | 그 레코드를 노치에 꽂아 재생. 상자 사본 유지 |
| Cmd+클릭 | 노치의 레코드 | 상자에서 선택된 레코드와 맞바꾸기 |
| Cmd+클릭 | 상자 안의 레코드 | 노치 레코드와 맞바꾸기. 선택한 레코드가 노치로, 현재 레코드가 상자로 |
| 드래그 ↑ | 상자 안의 레코드 | 노치 쪽으로 올리면 꽂아 재생 |
| 드래그 ↓ | 상자 안의 레코드 | 상자 아래로 내리면 조용히 빠져나감(삭제) |
| Cmd+스크롤 | 노치 | 복제 (스크롤 대안) |
| Cmd+스크롤 | 상자 | 상자 안 레코드 이동/탐색 (세부 매핑은 미정) |
| 일반 드래그/스크롤 | — | 기존 동작 그대로 |

**토글의 의미.** 그냥 클릭은 "한 장 더 찍기", Cmd+클릭은 "자리 바꾸기"다. 같은
두 레코드를 다시 Cmd+클릭하면 원래 자리로 돌아간다. 그냥 클릭은 누를 때마다
사본이 하나씩 늘어난다(중복 정책은 9장).

**Cmd 타이밍.** Cmd는 클릭 전에 눌러도 되고, 클릭/드래그 중에 눌러도 된다.
최종 판정은 **mouse-up(또는 드롭) 시점의 Cmd 상태**로 한다. 클릭 중에 Cmd를
누르거나 떼면 미리보기(대상 레코드, 화살표, 드롭존 라벨)가 즉시 바뀐다.
`OverlayContentView`에 `flagsChanged`를 추가해 이 토글을 감지한다.

### 스크롤 충돌 주의

현재 일반 두 손가락 스크롤은 이미 **열기 / 닫기 / 탐색 / confirm / 플레이어 부르기**에
전부 쓰인다. 마지막 항목은 레코드가 닫혀 있고 트랙이 있을 때의 위로 스와이프다. 따라서
"스크롤로 복제"를 넣으려면 **Cmd+스크롤**로 한정해야 한다. Cmd 없이 스크롤에 복제를
얹으면 기존 제스처와 정면으로 충돌한다.

### 클릭 분기 순서

`handleMouseDown`에서 **수정자와 클릭 대상을 가장 먼저** 검사한다.

- Cmd가 눌려 있으면 "바꾸기" 후보로 등록하고, 기존 클릭(재생/일시정지, 닫기,
  confirm)으로 내려가지 않는다.
- Cmd가 없으면 "빼기" 후보로 등록한다. 단, 레이블 클릭(재생/일시정지)은 그대로
  유지하고, **본체 클릭만** 빼기로 쓴다.
- 드래그로 이어지면 기존 분류(탐색/떼어내기)와 충돌하지 않도록 Cmd 상태와
  시작점을 기준으로 분기한다.

**기존 "본체 클릭 = 닫기"와의 충돌.** 이 기능을 넣으면 latched 상태의 본체 클릭이
"닫기"에서 "상자로 빼기"로 바뀐다. 닫기는 이미 **위로 끌기 / 위로 스크롤**로도
가능하므로 그쪽으로 남길 수 있다. 이 변경을 받아들일지는 9장의 결정 사항이다.

## 4. 상자 UI와 위치

### 후보

| 안 | 설명 | 장단점 |
| --- | --- | --- |
| **A. 노치 부착 드로어(권장)** | Cmd+클릭 때 노치 아래로 작은 상자가 열리고, 미니 레코드가 한 줄로 보임. 닫으면 사라짐 | 기존 패널 확장만으로 구현. 평소 화면을 차지하지 않음 |
| B. 상시 노출 트레이 | 노치 옆/아래에 상자 입구가 항상 보임 | 발견성 좋음. 작은 오버레이가 늘 떠 있음 |
| C. 자유 배치 | 레코드를 화면 아무 데나 떨어뜨려 둠 | 놀이성 좋음. 화면 전체 오버레이·클릭 통과·정리가 필요 |
| D. 별도 엣지 선반 | 화면 가장자리에 상자 창을 따로 띄움 | 여러 앱 위에서 유지 가능. 창 관리 복잡 |

**MVP는 A**를 권장한다. Cmd+클릭 → 상자 드로어가 열리고 → 레코드가 날아가 꽂히고 →
바깥을 클릭하거나 일정 시간 뒤 닫힌다. 상자가 비어 있으면 열리지 않거나 "빈 상자"만
잠깐 보여준다.

### 상자 안 표현

- 미니 레코드(지름 32~44pt)가 **한 줄**로 놓인다. 앨범 아트/레이블이 그대로 보인다.
- 호버하면 제목·아티스트.
- 상자 이름(예: "내 레코드 상자")과 개수를 표시한다.
- 개수가 많아지면 가로 스크롤 또는 살짝 겹친 팬(fan)으로 보여준다.
- 드래그로 순서를 바꾸면 그 순서가 플레이리스트 순서가 된다(후속).
- 여러 상자를 지원할 때는 상자 탭/박스 아이콘으로 전환한다(후속).

### 레코드가 날아가는 연출

그냥 클릭 시 노치 레코드에서 **복제본 한 장이 튀어나와** 상자로 날아가 꽂힌다.
원본은 그대로 남아 계속 돈다. 햅틱 1회, 상자 개수 증가. 중복이면 살짝 흔들리는
"이미 있음" 피드백.

### 데스크탑 장식 모드

- 상자는 로컬 메타데이터·아트워크 캐시로 렌더링되므로 **Music이 꺼져 있어도 보인다.**
- 상시 노출(트레이/엣지 선반)을 선택하면 화면 장식 요소로 쓸 수 있다.
- 재생을 누르지 않아도 레코드가 천천히 도는 등 시각 상태를 유지할 수 있다.
- 상시 노출 시 클릭 통과 범위와 화면 점유는 별도 결정(4장 후보 B/C).

## 5. 데이터 모델과 저장

### `CrateItem`

```swift
struct CrateItem: Codable, Identifiable {
    let id: UUID
    let persistentID: String
    let title: String
    let artist: String
    let album: String
    let duration: Double
    let sourceClass: String      // "file track" / "URL track" 등
    let addedAt: Date
    var artworkID: String?       // 로컬 캐시 파일 이름
}
```

- **artwork**: Music에서 읽은 이미지를 다운스케일해 Application Support에 캐시한다.
  트랙을 다시 찾지 못해도 상자에서는 레코드로 보여야 한다.
- **metadata**: 제목·아티스트·앨범·길이를 함께 저장해 Music이 꺼져 있어도 렌더링.
- **order**: 배열 순서 = 플레이리스트 순서.
- **중복 정책(미정)**: persistent ID 기준으로 중복을 막을지, 플레이리스트처럼 허용할지.

### `Crate`

```swift
struct Crate: Codable, Identifiable {
    let id: UUID
    var name: String
    var items: [CrateItem]
}
```

- v1은 상자 하나. 모델은 처음부터 여러 상자를 염두에 둔다.
- 저장 위치: `~/Library/Application Support/Umak/crates.json` (+ `artwork/`).
- 원자적 쓰기, 손상 시 빈 상자로 복구. `SelfChecks`로 인코딩/디코딩/중복/순서 검사.

## 6. Music 연동과 재생

### 복제는 로컬

복제 시점에 필요한 정보(제목·아티스트·앨범·길이·persistent ID·아트워크)만 읽는다.
Music의 상태나 사용자 데이터는 바꾸지 않는다.

**정체성은 항상 알 수 있다.** 복제 시점의 트랙 `properties`에서 이름·아티스트·앨범·
길이·장르·persistent ID·database ID·아트워크를 모두 읽는다. 그러므로 상자는
Music과 무관하게 레코드 라벨·아트워크·순서를 로컬에서 재현할 수 있고, 데스크탑
꾸미기 용도로도 문제없다.

**모르는 것은 "나중에 그 곡을 다시 재생하라고 명령할 수 있는가"뿐이다.** Apple Music
스트리밍 트랙은 현재 재생 큐(소스 `Scripting`)에만 존재하고 라이브러리에는 없으며
(검증: `Library: 240 tracks`, `Scripting: 0 tracks`, `inLibrary=no`), `address`
(스트림 URL)도 읽히지 않는다. persistent ID는 알지만, 나중에 그 ID로 트랙을 찾을
수 없다는 뜻이다. 로컬 라이브러리/파일 트랙은 이 문제가 없다.

### 다시 꽂아 재생하기

- **로컬 라이브러리/파일 트랙**: `persistent ID`로 찾아 재생할 수 있다.
  ```applescript
  tell application "Music"
      play (first track of library playlist 1 whose persistent ID is "...")
  end tell
  ```
- **Apple Music 스트리밍 트랙**: 현재 재생 중인 트랙을 확인한 결과
  `URL track`이고, `library playlist 1`에서 찾히지 않았으며(`inLibrary=no`,
  `libraryMatch=no`), `address` 읽기도 환경에 따라 실패했다(-1728/-1700).
  즉 **나중에 다시 꽂아 재생하는 것이 보장되지 않는다.**
- 대응 후보:
  1. persistent ID로 먼저 찾고, 있으면 재생 (라이브러리에 추가된 곡은 성공 가능).
  2. 재생 가능한 Music URL을 확보할 수 있으면 저장해 두고 `open location`으로 연다.
  3. MusicKit / Apple Music API를 쓰는 별도 경로 (개발자 토큰·권한 필요, 큰 작업).
  4. 실패하면 상자에서 레코드를 지우지 않고 "지금은 다시 재생할 수 없어요"를 조용히
     표시한다. 시각적 수집은 유지된다.

**MVP 권장**: 1 + 4. 재생 가능한 곡은 재생하고, 스트리밍 곡은 실패를 정직하게
알린다. 재생 보장이 필요해지면 2/3을 검토한다.

### 플레이리스트로 발전

- **Umak 내부 플레이리스트**: 상자 하나가 곧 순서 있는 목록이다. "이 상자 재생"은
  순서대로 한 곡씩 꽂아 재생하는 방식. v1 범위 밖.
- **Music 플레이리스트로 내보내기(추가 전용)**: 사용자가 명시적으로 요청할 때
  `make new user playlist` 후 재생 가능한 트랙을 추가한다. 스트리밍 전용 곡은
  추가에 실패할 수 있으므로 결과를 요약해 보여준다. 삭제·`disliked`는 하지 않는다.
- **여러 상자 = 여러 플레이리스트**: 상자마다 이름을 붙이고, 레코드를 상자 사이로
  드래그해 옮길 수 있게 한다(후속).

### 구현 시 함정

- Cmd+클릭은 `mouseDown`에서 **가장 먼저** 검사해 기존 클릭 경로를 오염시키지 않는다.
- 상자 드로어가 열려 있는 동안 패널 입력 영역이 넓어진다. 드로어 바깥 클릭은
  "닫기"로만 처리하고, 다른 앱 클릭을 막지 않도록 열린 동안만 입력을 받는다.
- 드로어가 닫히면 창을 idle 프레임으로 되돌린다. 상시 노출을 선택하면 이 단계가 달라진다.
- 상자 항목의 아트워크 캐시가 없으면 `RecordTexture`의 생성 레이블로 대체한다.
- Music이 꺼져 있거나 트랙이 사라져도 상자는 로컬 데이터로 계속 보여야 한다.
- 복제 시점의 트랙이 바뀌는 중일 수 있다. `persistentID`와 메타데이터를 한 번에
  읽어 일관된 스냅샷을 만든다.

## 8. 발전 경로

1. **v1** — Cmd+클릭 복제, 상자 하나, 드로어 UI, 꽂기/빼기, 로컬 저장, 재생 가능한
   곡만 재생.
2. **v2** — 순서 바꾸기, 상자 재생(연속), 중복 정책 확정, 여러 상자.
3. **v3** — Music 플레이리스트로 내보내기, 기존 플레이리스트를 상자로 가져오기,
   MusicKit 기반 스트리밍 재생 보장.

## 9. 열린 결정

1. **본체 클릭 충돌**: 현재 latched 상태의 본체 클릭 = 닫기. 이를 "빼기"로 바꿀지
   (권장: 바꾸고, 닫기는 위로 끌기/스크롤로 유지) vs 기존 닫기를 유지하고 빼기는
   Cmd+클릭에만 둘지.
2. **"빼기"의 의미**: 복제(권장, 원본 유지) vs 이동(노치가 빔).
3. **상자 레코드 그냥 클릭**: 재생 + 상자 사본 유지(권장) vs 상자에서 꺼내기(제거).
4. **Cmd+클릭 "바꾸기"의 정확한 교환 규칙**: 클릭한 상자 레코드 ↔ 현재 노치 레코드.
   현재 곡이 상자에 없으면 새로 담을지, 임시 슬롯에 둘지.
5. **Cmd 판정 시점**: mouse-up(권장, 클릭 중 토글 가능) vs mouse-down.
6. **상자 노출**: 드로어(권장) vs 상시 트레이 vs 자유 배치.
7. **중복 정책**: 같은 곡을 두 번 담을 수 있게 vs 한 번만.
8. **Cmd+스크롤 매핑**.
9. **재생 실패 시**: 조용한 메시지(권장) vs 담기 자체를 막기 vs MusicKit 도입.
10. **플레이리스트 내보내기**: v1은 로컬 상자만 vs 처음부터 Music 플레이리스트 생성.
11. **상자 최대 개수/표시 개수**.

## 10. 구현 순서와 예상

1. `CrateItem`/`Crate` 모델 + JSON 저장 + `SelfChecks` (UI 없이)
2. 클릭/Cmd+클릭 분기 + Cmd 토글 미리보기 + 복제/교환 스냅샷 + 날아가는 연출
3. 상자 드로어 + 미니 레코드 + 닫기/열기
4. 드래그 ↑ 꽂기(재생) / 드래그 ↓ 빼기(미끄러짐)
5. 재생 해석 실패 처리 + 데모 + 로컬라이제이션

예상: **MVP 2~3일**, 순서 바꾸기·여러 상자·내보내기까지 **+2~3일**.

## 11. 테스트와 데모

- 같은 곡을 두 번 복제했을 때의 정책.
- 로컬 파일 트랙 / 라이브러리 트랙 / Apple Music 스트리밍 트랙 각각 복제 후 재꽂기.
- 앱 재실행 후 상자 복원, Music 종료 상태에서 상자 렌더링.
- 본체 클릭이 빼기로 바뀌었을 때 닫기(위로 끌기/스크롤)가 여전히 되는지.
- 클릭 중 Cmd를 누르고 떼는 토글이 미리보기와 최종 동작에 모두 반영되는지.
- 드로어가 열린 동안 다른 앱 클릭을 막지 않는지, 닫힌 뒤 idle 프레임 복귀.
- 빼기 연출이 파손 없이 끝나는지, 상자 개수/저장이 맞는지.
- 데모: 꺼내기 → Cmd+클릭 복제 → 상자 열림 → 꽂기 → 빼기.
