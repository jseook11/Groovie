# 바탕화면 레코드 (Option+드래그 복사) 설계 노트

상태: **구현 반영** · 2026-10-23
이 작업은 `record-break.md` / `record-crate.md`의 아이디어와 **무관하게** 진행한다.

## 0. 한 줄 요약

노치에서 레코드를 **완전히 꺼낸 뒤**, 그 레코드 위에서 **Option(⌥)을 누른 채 클릭해
드래그하면** 재생 중인 곡의 **장식용 사본 한 장**이 튀어나와 포인터를 따라온다.
바탕화면에 놓으면 그 자리에 레코드가 남는다. 같은 레코드에서 **Option을 누른 채
드래그하지 않고 한 번 클릭하면**, 같은 곡이 **레코드가 40% 나온 앨범 슬리브**로
바탕화면에 놓인다. 노치의 원본과 재생 상태는 전혀 바뀌지 않는다. 바탕화면의 사본은
**Option+드래그로 움직이고**, **Option+클릭으로 열린 슬리브 → 닫힌 슬리브 →
레코드 판 → 열린 슬리브를 순환한다**. **Option 없이는 아무 동작도 하지 않는다**.
상단 노치 상호작용 영역으로 끌어다 놓으면 삭제된다.

**소스는 완전히 열린 레코드다.** 고정(pin)된 레코드뿐 아니라, 고정 전이라도 레코드가
완전히 나와 있는 상태(놓은 뒤 1초 확인 창을 기다리는 상태 포함)에서 동작한다. 닫힌
레코드나 아직 덜 나온 레코드에서는 Option이 복사/포장을 뜻하지 않는다.

**제스처 중에는 닫히지 않는다.** 고정되지 않은 레코드는 원래 놓으면 잠시 뒤 노치로
돌아간다. Option+클릭/드래그가 진행되는 동안에는 이 복귀를 잡아두어 레코드가 화면에
남아 있게 한다. 제스처가 끝나면 원래의 1초 확인 창을 다시 열어, 사본을 만든 뒤
자연스럽게 닫히도록 한다.

바탕화면의 사본은 같은 슬리브 모델의 세 가지 상태를 가진다.

| 형태 | 만드는 법 | 표현 |
| --- | --- | --- |
| **레코드 판** | ⌥+클릭 **드래그** → 원하는 위치에 놓기 | 지금 노치에서 렌더하던 바이닐 한 장(180×180)을 **정적 이미지**로 |
| **열린 슬리브** (기본) | ⌥+**단발 클릭**, 또는 레코드 판을 ⌥+클릭 | 커버 200×200 + 오른쪽으로 72pt(180pt의 40%) 나온 바이닐. 아이템 272×200 |
| **닫힌 슬리브** | 열린 슬리브를 ⌥+클릭 | 커버 200×200만. 바이닐은 전혀 그리지 않는다 |

Option+클릭은 **열린 슬리브 → 닫힌 슬리브 → 레코드 판 → 열린 슬리브** 순으로 무한히
순환한다.

모든 상태가 **순수 장식물**이다. 회전하지 않고, 재생/탐색/곡 넘기기와 무관하며,
렌더링 이후 프레임 타이머를 돌리지 않는다. CPU 소모는 사실상 0에 수렴한다.

## 1. 범위와 원칙

### 하는 것

- **완전히 열린** 레코드 위에서 Option+클릭 드래그로 현재 트랙의 **레코드 판 사본**을
  만들어 바탕화면에 놓는다. 고정된 레코드와 고정 전 완전히 열린 레코드 모두 해당한다.
- **완전히 열린** 레코드 위에서 Option+단발 클릭으로 같은 곡을 **열린 슬리브(커버 +
  40% 나온 레코드) 형태**로 바탕화면에 놓는다. 드래그 없이도 “앨범을 소유”하는 경로다.
- 사본은 앱을 재실행해도 남는다(메타데이터 + 아트워크 + 위치 + 형태 + 열림 상태 저장).
- 사본을 Option+드래그로 옮긴다.
- 사본을 Option+클릭해 **열린 슬리브 → 닫힌 슬리브 → 레코드 판 → 열린 슬리브**를
  순환한다.
- 사본을 상단 노치 영역으로 끌어다 놓으면 삭제한다.
- 상태 메뉴에서 바탕화면 레코드를 한 번에 정리한다.

### 절대 하지 않는 것 (이번 범위)

- 사본을 클릭해 재생/일시정지, 탐색, 곡 넘기기, 닫기.
- 사본을 노치에 다시 꽂아 재생하거나 플레이리스트로 승격.
- 사본과 원본의 실시간 동기화(사본은 복사 시점의 스냅샷).
- Music의 라이브러리/플레이리스트/`disliked` 변경.

사본은 **순수 장식물**이다. 회전하지 않고, 재생 상태도 없다. Option을 누른 채 마우스를
올리면 움직일 수 있다는 힌트만 조용히 보여준다.

### 기존 문서와의 관계

`record-break.md`(파손)와 `record-crate.md`(크레이트/플레이리스트)는 이 작업의
전제가 아니다. 둘 다 단발성 아이디어 메모이고, 이 기능은 그 설계를 고려하지 않고
독립적으로 만든다. 나중에 별도로 구현하더라도 이 기능의 데이터 모델이나 제스처를
공유할 필요가 없다.

## 2. 제스처 지도

| 입력 | 위치 | 동작 |
| --- | --- | --- |
| ⌥+클릭 드래그 | **완전히 열린** 레코드(고정 포함) | **레코드 판** 사본을 꺼내 포인터로 운반 |
| ⌥+클릭 (이동 없음, ≤ 4pt) | **완전히 열린** 레코드(고정 포함) | **열린 슬리브**(커버 + 40% 나온 레코드)를 기본 자리에 놓기 |
| 드래그 후 놓기 | 바탕화면(어느 화면이든) | 그 자리에 레코드 판 사본 배치 |
| 드래그 후 놓기 | 노치 스트립으로 되돌리기 | 복사 취소(사본을 만들지 않음) |
| ⌥+클릭 드래그 | 바탕화면의 사본 | 사본 이동 |
| 놓기 | 상단 노치 삭제 존(사본 중심) | 사본 삭제 |
| 일반 클릭/드래그 | 바탕화면의 사본 | 아무 동작 없음(클릭은 소비, z-order 변화 없음) |
| ⌥+단발 클릭 | 바탕화면의 사본 | **열린 슬리브 → 닫힌 슬리브 → 레코드 판 → 열린 슬리브** 순환 |
| 일반 클릭/스크롤/드래그 | 완전히 열린 레코드 | 기존 동작 그대로 |
| ⌥+클릭/드래그 | 닫힌/덜 열린 레코드 | 기존 동작 그대로(Option은 특별한 의미 없음) |

**Option 타이밍.** 판정은 `mouseDown` 시점의 `NSEvent.modifierFlags`로 한다.
드래그를 시작한 뒤에 Option을 눌러도 복사로 바뀌지 않는다. 우발적인 복사를 막기
위해 “누른 채로 시작”만 인정한다.

**소스 조건.** 복사/포장은 다음 중 하나일 때 시작한다.
- `latched`(고정됨)
- `phase == .grabbed`이고 `exposure >= fullExposure`(완전히 열림)
- `pendingConfirmUntil != nil`(놓은 뒤 1초 확인 창)

닫힌 레코드나 덜 열린 레코드에서는 Option이 기존 동작을 바꾸지 않는다.

**제스처 중 열린 상태 유지.** 고정되지 않은 완전 열림 레코드에서 Option 제스처를
시작하면 `pendingConfirmUntil`을 잡아두어(만료 취소) 제스처가 끝날 때까지 레코드가
올라가지 않게 한다. 제스처가 끝나면 1초 확인 창을 다시 열어, 원래대로 잠시 뒤
닫히게 한다. 고정된 레코드는 그대로 고정을 유지한다.

**드래그와 단발 클릭의 구분.** Option을 누른 채 `mouseUp`까지 이동이
`clickSlop`(4pt) 이하면 **포장**, `pullStartDistance`(8pt) 이상이면 **레코드 판**
드래그다. 그 사이(4~8pt)는 드래그로 인정하지 않고 포장도 하지 않는다(손떨림 보호).

**레이블 클릭과의 관계.** 완전히 열린 레코드에서는 Option이 눌려 있으면 레이블
위에서 시작해도 재생/일시정지가 아니라 복사/포장 후보가 된다. 기존 “레이블 클릭 =
재생 토글”은 Option 없이 누를 때만 유지한다.

**기존 제스처와의 충돌.** 완전히 열린 상태의 `handleMouseDown`에서 Option을 먼저
검사하고, 복사 세션이면 기존 `latched`/`pendingConfirm` 분기(탐색/닫기/재생 토글)로
내려가지 않는다. 따라서 복사 드래그가 닫기·고정·탐색·재생 토글을 건드리지 않는다.

## 3. 복사 드래그 흐름

1. **완전히 열린 레코드** 위에서 `mouseDown`에 Option이 있으면 `CopyDragSession`을
   만들고 기존 latched/pending 세션 생성은 건너뛴다. 이때 `pendingConfirmUntil`을
   잡아두어 제스처 중 복귀를 막는다.
2. 이동이 `pullStartDistance`(8pt)를 넘으면 고스트 레코드를 띄운다.
   - 레코드 중심에서 한 장이 겹쳐 나온다.
   - 원본 레코드는 열린 자리에서 계속 재생된다.
3. 고스트는 포인터를 따라다니며, 원본 레코드/재생/회전은 그대로 둔다.
4. `mouseUp`:
   - 이동이 `clickSlop`(4pt) 이하: **열린 슬리브**를 기본 자리에 만든다(3.1).
   - 이동이 4pt 초과 8pt 미만: 아무것도 만들지 않는다(손떨림 보호).
   - 노치 스트립(`geometry.idleFrame`) 안: 취소한다(사본을 노치로 되돌리는 짧은
     흡입 연출). 바탕화면 사본 삭제에 쓰는 더 큰 삭제 존은 복사 드래그에 적용하지
     않는다. 소스 레코드가 그 존 안에 있기 때문이다.
   - 그 밖: 드롭 지점에 **레코드 판** 사본을 만든다.
5. 제스처가 끝나면: 원본이 고정되어 있었다면 그대로 둔다. 고정 전이었다면 1초 확인
   창을 다시 열어 잠시 뒤 원래대로 닫히게 한다.
6. `finishLostDrag`(mouse-up 유실)에서도 같은 복원을 하고, 고스트만 지운다.

### 3.1 열린 슬리브 (Option+단발 클릭)

- 드래그 없이 Option+클릭하면, 현재 곡의 **열린 슬리브**(커버 + 40% 나온 레코드)가
  **기본 자리**에 나타난다.
- 기본 자리: 화면 상단 중앙, 삭제 존 바로 아래.
  - 중심 `x = 화면 중앙`
  - 중심 `y = screen.maxY - (notchHeight + 80) - 아이템높이/2 - 16`
  - 이미 사본이 있으면 오른쪽 아래로 24pt씩 캐스케이드하고, 화면 안으로 클램프한다.
  - 드래그로 원하는 곳으로 옮길 수 있다.
- 연출: 0.18초 페이드 인(1회성) 후 완전히 정적이 된다. 끝나면 타이머/애니메이션을
  남기지 않는다. (레코드가 슬리브 안으로 들어가는 모션은 후속 폴리시)
- 나중에 ⌥+클릭으로 **닫힌 슬리브 → 레코드 판 → 열린 슬리브** 순으로 순환한다.
  열림/닫힘에서는 커버 중심(앵커)이 그대로이고, 판으로 바뀌면 판 중심이 앵커가 된다.
- 재생 중인 트랙이 없으면 아무 일도 하지 않는다.
- 완전히 열리지 않은 레코드에서는 이 동작이 시작되지 않는다. 먼저 레코드를 충분히
  꺼내야 한다.
- 같은 곡을 여러 번 포장해도 된다(독립 사본).

### 3.2 기본 자리와 드롭 지점

- **단발 클릭(포장)**: 위의 기본 자리. 포인터 위치를 쓰지 않는다.
- **드래그(레코드 판)**: 포인터를 놓은 전역 좌표. 화면의 `visibleFrame` 안으로
  클램프한다. 여러 화면이면 포인터가 있는 화면을 쓴다.
- 두 경우 모두 사본의 중심이 삭제 존 안에 들어가지 않게 기본 배치를 보정한다.

### 고스트 창

- `CopyGhostPanel`: borderless, non-activating, transparent, `ignoresMouseEvents = true`.
- 레벨: `statusBar + 2` 수준. 다른 앱 위에서도 드래그 중에는 보여야 한다.
- `collectionBehavior`: `canJoinAllSpaces`, `fullScreenAuxiliary` (드래그 중 전체 화면
  앱 위에서도 보이도록).
- 표시 내용: `VinylDiscView`와 같은 렌더러로 만든 정적 레코드 한 장. 원본과 같은
  라벨/아트워크/스킨을 쓴다.
- 마우스 이벤트를 받지 않으므로, 드래그 이벤트는 계속 노치 패널로 들어온다.

## 4. 바탕화면 레코드 창

### 표현과 렌더링 (CPU ≈ 0)

사본은 **만들 때 한 번 렌더링한 정적 이미지**를 창에 붙이는 방식으로 그린다.
SwiftUI `@State`/`@ObservedObject`로 매 프레임 다시 그리지 않고, 회전·프레임 타이머를
두지 않는다. Option hover/drag의 0.15초 스케일 전환만 Core Animation으로 처리한다.

| 형태 | 아이템 크기 | 이미지 |
| --- | --- | --- |
| `.disc` (레코드 판) | 180×180pt | `RecordTexture`로 만든 바이닐 한 장. 지금 노치에서 보던 것과 같은 라벨/아트워크/스킨 |
| `.sleeve`, `recordOut == true` (열린 슬리브) | 272×200pt | 왼쪽 커버 200×200, 오른쪽으로 72pt(180pt의 40%) 나온 불투명 바이닐. 커버가 바이닐 위에 그려지고, 커버 입구 그림자가 바이닐에 드리운다 |
| `.sleeve`, `recordOut == false` (닫힌 슬리브) | 200×200pt | 커버만. 바이닐은 전혀 그리지 않는다 |

- 아트워크가 있으면 커버는 아트워크를 정사각형으로 채운다.
- 아트워크가 없으면 `RecordTexture`의 생성 레이블과 같은 팔레트/타이포로
  **생성 커버**를 만든다(제목·아티스트·`SIDE A`·`33⅓ RPM`).
- 2x 백킹 기준으로 렌더링해 Retina에서도 선명하게 한다.
- 스킨을 바꾸면 모든 사본을 **한 번만** 다시 렌더링한다. 그 외에는 이미지가
  바뀌지 않는다. 재렌더링은 한 장씩 런루프 턴을 나눠 진행하므로, 사본이 많아도
  메뉴/UI가 멈추지 않는다(레코드당 약 5–10ms).
- 앱 시작 시 저장된 사본 복원도 같은 방식으로 한 장씩 진행한다. 메뉴바 아이콘과
  노치가 먼저 뜨고, 사본은 그 뒤에 차례로 나타난다.
- 아트워크 파일은 복사 시점 스냅샷이라 재생 중 트랙이 바뀌어도 사본은 그대로다.
- 이미지 크기는 아이템 + `shadowPadding`(34pt) × 2다. 열린 슬리브 340×268, 닫힌
  슬리브 268×268, 레코드 판 248×248. 창은 이 이미지를 확대/축소하지 않는다.

### 깊이 (Depth)

- 광원은 하나: **좌상단**. 모든 그림자와 하이라이트가 같은 방향을 따른다.
- 사본은 하나의 실루엣에서 세 그림자 층을 합성한다.
  - **ambient**: 불투명도 0.10, blur 38pt, offset (0, -2)
  - **key**: 0.26, blur 16pt, offset (5, -7)
  - **contact**: 0.38, blur 2.5pt, offset (0, -1)
- **열린 슬리브**: 커버 오른쪽 입구에서 나온 13pt 그라디언트가 노출된 바이닐을 덮어,
  레코드가 보드 아래에 들어가 있음을 보여준다. 커버 가장자리에는 보드 두께(어두운 면과
  밝은 절단면)와 입구 슬릿이 있다.
- **닫힌 슬리브**: 커버만 그리므로 바이닐 가장자리나 바이닐 그림자가 비치지 않는다.

### 층과 동작

- 사본 하나당 `DesktopRecordWindow` 하나. 내용은 정적 레코드.
- 창 레벨: `NSWindow.Level.desktopIcon + 1` 계열. **Finder 데스크탑 아이콘 위, 일반 앱
  창 아래**에 놓여 “바탕화면 장식”으로 읽히면서도, 다른 앱이 포커스를 가져가도 클릭이
  Finder에 먹히지 않는다.
  - 정확한 레벨은 스파이크로 검증했다(8장).
- `isOpaque = false`, `backgroundColor = .clear`, `hasShadow = false`.
  그림자는 렌더러가 이미지 안에 그려 창 밖으로 잘리지 않게 한다.
- `.nonactivatingPanel` 또는 키가 되지 않는 `NSPanel`로 포커스를 훔치지 않는다.
- **스페이스**: `.canJoinAllSpaces`로 모든 데스크탑(스페이스)에서 같은 사본이 보인다.
  스페이스는 공개 API로 식별할 수 없으므로, 위치는 화면 전역 좌표만 저장한다.
- 창 크기: 아이템 크기 + `shadowPadding`(34pt) × 2. 열린 슬리브 340×268, 닫힌 슬리브
  268×268, 레코드 판 248×248. `acceptsFirstMouse = true`.

### 이벤트 수신과 클릭 통과

- 사본 창은 **항상 마우스 이벤트를 받는다**(`ignoresMouseEvents = false`). 그래야
  커서를 사본 위에 올려둔 채 Option을 눌러도, 커서를 밖으로 뺐다 다시 넣지 않고 바로
  클릭/드래그할 수 있다.
- **Option이 없으면 아무 동작도 하지 않는다.** 일반 클릭/드래그는 사본을 올리거나
  이동시키지 않으며, z-order도 바뀌지 않는다. 클릭은 현재 사본 영역에서 소비된다.
- 히트 테스트는 **실루엣만** 통과시킨다. 닫힌 슬리브는 커버 사각형, 열린 슬리브는
  커버 + 노출된 바이닐, 레코드 판은 원이다. 실루엣 밖(투명 그림자 여백)의 클릭은
  아무 동작도 하지 않지만, 현재는 창이 이벤트를 삼킨다.
- 이벤트 폴링 타이머는 없다. 유휴 시 CPU ≈ 0.
- Option 없이 클릭이 사본 영역을 통과해 Finder/데스크탑에 닿는 것과, 겹친 사본 사이의
  진정한 클릭 통과는 후속 과제다.

### 형태 전환

- 바탕화면 사본 위에서 **Option+클릭**(이동 ≤ 4pt)하면 세 상태를 순환한다:
  **열린 슬리브 → 닫힌 슬리브 → 레코드 판 → 열린 슬리브**.
- **앵커 의미**: 앵커는 `.sleeve`면 커버 중심, `.disc`면 레코드 판 중심이다. 열고
  닫아도 커버 앵커는 움직이지 않고, 창은 **오른쪽으로만** 커지거나 작아진다. 닫힌
  슬리브에서 판으로 바뀌면 판이 커버 중심에 놓이고, 판에서 열린 슬리브로 바뀌면
  커버가 판 중심에 놓인다.
- 새 크기가 화면 밖으로 나가지 않게 앵커를 클램프한다.
- `style`과 `recordOut`은 저장소에 함께 기록되어 앱을 다시 실행해도 유지된다.
- Option+드래그(이동 > 4pt)는 상태 전환이 아니라 이동이다.

### 호버/이동 피드백

- **Option을 누른 채** 포인터가 사본 위에 있으면 사본이 1.02배로 살짝 떠오르고
  `openHand` 커서가 된다. 링은 그리지 않는다. Option 없이 hover하면 시각 반응이 없다.
- 사본이 다른 앱 창에 가려져 있으면(최상위 창이 아니면) hover 반응도 없다.
- Option+드래그 중: 1.04배로 떠오르고 커서는 `closedHand`, 창 레벨을 일시적으로
  `statusBar + 2`로 올려 다른 앱 위에서도 사본이 보이게 한다. 놓으면 데스크탑 레벨로
  되돌린다. 얇은 링은 드래그 중이거나 삭제 존에 들어갔을 때만 보인다.
- 이동은 포인터 델타에 1:1로 따라간다. 관성/스냅 없음.
- 놓을 때 화면 밖으로 나가지 않게 클램프한다.

## 5. 삭제(정리)

- **삭제 존**: 화면 상단 중앙, 노치를 감싸는 영역.
  - `x`: 노치 중심 기준 `max(notchWidth + 160, 320)` 폭
  - `y`: 화면 맨 위부터 `notchHeight + 80` 높이
  - 노치가 없는 화면도 같은 규칙(상단 중앙).
- 바탕화면 사본을 드래그하는 동안 **사본의 중심**이 삭제 존에 들어오면:
  - 노치 쪽에 옅은 “놓아서 정리” 하이라이트를 띄운다(별도 얇은 패널 또는 기존
    노치 큐 재사용).
  - 사본은 살짝 어두워지고 노치 쪽으로 빨려 들어갈 준비를 보여준다.
- 놓으면: 노치로 빨려 들어가는 0.18초 연출 → 창 닫기 → 저장소에서 제거 → 햅틱.
- 삭제는 되돌릴 수 없지만, 같은 곡을 다시 Option+드래그하면 되므로 확인 창은
  띄우지 않는다.
- 여러 장을 한 번에 지우려면 상태 메뉴의 **바탕화면 레코드 정리**를 쓴다(확인 있음).

## 6. 데이터 모델과 저장

```swift
struct DesktopRecord: Codable, Identifiable {
    let id: UUID
    let track: TrackSnapshot
    var style: DesktopRecordStyle   // .disc | .sleeve
    var position: CGPoint           // 앵커: .disc는 판 중심, .sleeve는 커버 중심
    var screenID: String?           // CGDirectDisplayID 문자열
    var recordOut: Bool             // .sleeve의 레코드 열림 상태 (기본 true)
    let createdAt: Date
}

struct DesktopRecordDocument: Codable {
    static let currentVersion = 2
    var version: Int
    var records: [DesktopRecord]
}

enum DesktopRecordStyle: String, Codable {
    case disc       // ⌥+드래그로 만든 정적 레코드 판
    case sleeve     // ⌥+단발 클릭으로 만든 앨범 슬리브(열림/닫힘)
}

struct TrackSnapshot: Codable {
    let persistentID: String    // NowPlaying.trackID
    let title: String
    let artist: String
    let album: String
    let duration: Double
    var artworkFile: String?    // artwork/ 안의 상대 파일명
}
```

- `.sleeve`의 합성 이미지는 저장하지 않고, 저장된 메타데이터 + 아트워크로 시작할 때
  다시 렌더링한다(파일 수를 줄이고 스킨 변경도 반영).
- `.disc`와 `.sleeve`는 같은 사본 모델을 공유하고 `style`과 `recordOut`만 다르다.
  이동/삭제/저장 규칙은 동일하다.

- 저장 위치: `~/Library/Application Support/Groovie/desktop-records.json`
  - 아트워크: 같은 폴더의 `artwork/<recordID>.png` (최대 512px, PNG)
- 최상위에 `version`을 두어 마이그레이션 여지를 남긴다.
- 쓰기는 원자적(`Data.write(options: .atomic)`). 드래그 중에는 저장하지 않고
  **놓을 때 한 번만** 저장한다. 생성/삭제/형태·열림 상태 변경은 즉시 저장.
- 손상된 JSON: 원본을 `desktop-records.corrupt-<timestamp>.json`으로 옮기고 빈
  목록으로 시작한다.
- 아트워크가 없거나 읽기에 실패하면 `RecordTexture`의 생성 레이블로 대체한다
  (제목/아티스트 기반). 아트워크 파일이 사라져도 레코드는 보인다.
- 같은 곡을 여러 번 복사해도 된다. 각 사본은 독립 UUID를 가진다.
- 안전 상한: 100장. 넘으면 새 복사를 거부하고 메뉴에 안내한다(런어웨이 방지).

### 영속성 (Persistence)

- 문서 버전은 **2**다. 각 레코드는 `recordOut`을 가지며, 필드가 없으면 `true`로
  디코드한다(기본값은 열린 상태).
- 저장되는 `position`은 아이템 중심이 아니라 **앵커**다. `.sleeve`는 커버 중심,
  `.disc`는 판 중심이다. 그래서 열고 닫아도 커버가 움직이지 않는다.
- **v1 마이그레이션**: v1은 아이템 중심을 저장했고 `recordOut`이 없었다. 디코드할 때
  각 `.sleeve`의 x를 **-35pt**(270pt 아이템 중심 → 200pt 커버 중심) 옮기고, `.disc`
  위치는 그대로 두며, 모든 레코드를 `recordOut = true`로 시작한다. 디코드된 문서는
  원래 버전(1)을 보고하므로 저장소가 이를 한 번 업그레이드해 **버전 2로 다시 쓴다**.

### 화면/위치 복원

- 저장된 `screenID`가 있으면 그 화면을 찾는다. **주 화면(메인 디스플레이)이 바뀌어도
  사본은 원래 화면에 남는다.**
- 화면이 사라졌으면 그 좌표를 포함하는 화면 → 주 화면 순으로 대체하고
  `visibleFrame` 안으로 클램프한다.
- 화면 구성 변경 알림(`didChangeScreenParametersNotification`)에서 모든 사본을 다시
  클램프한다. 디스플레이 분리/재연결, 해상도 변경, 배치 변경을 모두 포함한다.
- **앱 재실행**: JSON에서 복원한다. 아트워크 파일이 없으면 생성 커버/레이블로
  대체하므로 Music이 꺼져 있어도 보인다.
- **여러 스페이스**: `.canJoinAllSpaces`로 모든 스페이스에 같은 사본이 보인다.
  스페이스별 위치는 저장하지 않는다(공개 API가 없다).
- 아이템 전체가 `visibleFrame` 안에 들어오도록 클램프한다. 화면이 작아지거나
  배치가 바뀌어도 사본이 완전히 사라지지 않는다.

- 햅틱: `NSHapticFeedbackManager` (기존 `performHaptic` 패턴).
- 로컬라이제이션: `L10n.t(.key)`.

## 8. 구현 순서

1. **데이터 계층** — 모델(`style` 포함), 저장소, 아트워크 캐시, 커버/레코드 렌더러,
   클램프/삭제 존/기본 자리 순수 함수, `SelfChecks`. UI 없이 `make test` 통과.
2. **바탕화면 사본 창** — 저장된 사본을 데스크탑 레벨에 정적 이미지로 띄우고,
   재실행 후 복원. `.disc`와 `.sleeve`(열림/닫힘) 상태. 앱 시작/종료, 화면 변경,
   스킨 변경 시 1회 재렌더링. 메뉴의 “모두 정리”.
3. **노치에서 복사/포장** — modifier 전달, Option 최우선 분기, 복사 세션, 고스트 패널,
   드래그 드롭 시 레코드 판 생성, **단발 클릭 시 열린 슬리브 생성**, 노치 드롭 시 취소.
4. **바탕화면 사본 조작** — Option+드래그 이동, Option+클릭 3상태 순환, 드래그 중
   레벨 상승, 삭제 존 하이라이트와 삭제, 화면 경계 클램프.
5. **폴리시** — Option hover 게이팅, 호버 힌트, 포장 1회성 애니메이션,
   로컬라이제이션, 데모, 문서(ux-guide/README), 수동 QA, CPU 유휴 측정.

**스파이크 결과(검증됨):** `CGWindowList`에서 사본 창이 `desktopIcon + 1`
(-2147483602) 레벨로 생성되는 것을 확인했다. Finder 아이콘 위, 일반 앱 창 아래에
놓이며, 창은 항상 마우스 이벤트를 받는다. Option이 없을 때 일반 클릭/드래그는 아무
동작도 하지 않는다(사본을 올리지 않는다). 전체 화면/스페이스는 `.canJoinAllSpaces`와
`.fullScreenAuxiliary`로 처리한다.

## 9. 열린 결정 (기본안 표시)

1. **층**: **`desktopIcon + 1`(확정)**. Finder 아이콘 위, 일반 앱 창 아래. 8장에서
   검증했다.
2. **회전**: 모든 상태가 완전 정적(기본). 재생으로 오해될 여지를 없앤다.
3. **Option 없을 때 클릭**: **아무 동작도 하지 않음(확정)**. 일반 클릭은 사본을
   올리지 않고, 일반 드래그도 무동작이다. z-order는 Option+드래그 중에만 바뀐다.
   히트 테스트는 실루엣만 반응하며, 사본 영역 클릭 통과는 후속.
4. **복사 소스**: **완전히 열린 레코드(고정 포함)(확정)**. 닫힌 레코드나 덜 열린
   레코드에서는 Option이 특별한 의미를 갖지 않는다.
5. **드롭 위치**: 앱 창 위에 놓아도 그 전역 좌표에 사본 생성(기본). 앱 창에
   가려져도 바탕화면을 보면 있다.
6. **중복**: 같은 곡 여러 장 허용(기본). 최대 100장.
7. **삭제 확인**: 드래그 삭제는 확인 없음(기본), 메뉴 일괄 정리는 확인 있음.
8. **기존 문서**: 고려하지 않음(확정). `record-break.md` / `record-crate.md`와
   데이터·제스처를 공유하지 않는다.
9. **포장 형태**: **커버 + 40%(72pt) 나온 불투명 바이닐(확정)**. 열린 슬리브는
   272×200, 닫힌 슬리브는 200×200이며 바이닐을 그리지 않는다. 투명한 종이 슬리브는
   쓰지 않는다. 레코드 판은 ⌥+드래그로도 만들 수 있고, ⌥+클릭 순환의 한 상태이기도
   하다.
10. **포장 기본 위치**: 화면 상단 중앙 캐스케이드(기본) vs 화면 중앙 vs 포인터.
11. **포장 연출**: **0.18초 1회성 페이드 인(확정)**. 슬리브 삽입 모션은 후속.
12. **깊이**: **좌상단 단일 광원(확정)**. ambient/key/contact 세 그림자 층, 커버 입구
    그림자 13pt, 보드 두께와 입구 슬릿. 닫힌 슬리브에는 바이닐을 그리지 않는다.

## 10. 테스트와 QA

### 자동 (`make test`)

- `DesktopRecord` JSON 왕복(`style`, `recordOut`, 아트워크 경로 포함), 버전 필드.
- `recordOut`이 없는 레코드는 `true`로 디코드되는지.
- v1 문서 마이그레이션: 슬리브 x가 -35pt, 레코드 판 x는 불변, 둘 다 `recordOut == true`,
  디코드 직후 버전은 1, 재인코딩하면 버전 2.
- 열림/닫힘(`recordOut`)과 형태 전환(`updateStyle`)이 디스크에 저장되고 재로드 후
  유지되는지.
- 기하: 열린 슬리브 272×200, 닫힌 200×200, 판 180×180, `discRect` minX 92/20,
  `windowSize`가 축마다 68pt 추가, 앵커/창 원점 왕복, 열린 아이템 전체 클램프,
  열린 슬리브 `itemCenter`가 커버 앵커보다 36pt 오른쪽, `defaultSlot` 앵커 클램프.
- 렌더러 스모크: 이미지 크기가 `windowSize`와 일치(열린 340×268, 닫힌 268×268,
  레코드 판 248×248).
- 손상 JSON → 빈 목록 복구.
- 현재 버전보다 높은 문서 버전 → 로드하지 않고 파일을 `desktop-records.newer-v<N>-*`로
  보존한 뒤 빈 목록으로 시작.
- 레코드 하나만 깨진 경우(예: 알 수 없는 `style`) → 나머지 레코드는 유지하고, 원본을
  `desktop-records.recovered-*`로 보존한 뒤 복구본을 다시 쓴다.
- 형태 전환처럼 여러 필드를 동시에 바꾸는 업데이트가 한 번의 호출로 모두 저장되는지.
- 위치 클램프: 화면 안/밖, 화면 ID 없음/사라짐.
- 기본 자리 계산: 삭제 존과 겹치지 않음, 캐스케이드 후 화면 안.
- 삭제 존: 노치 중앙은 포함, 화면 중앙/하단은 제외.
- 복사 판정: 완전히 열린 상태에서 Option+이동 ≥ 8pt = 레코드 판, Option+단발 클릭 =
  포장, 닫힌/덜 열린 상태의 Option = 기존 동작, 4~8pt = 취소.
- 고정되지 않은 완전 열림 레코드에서 Option 제스처 중 `pendingConfirmUntil`이
  유지되어 복귀가 일어나지 않는지, 제스처 후 다시 1초 창이 열리는지.
- 중복 복사 시 UUID가 서로 다른지, 같은 곡의 `.disc`/`.sleeve`가 공존하는지.
- 커버 렌더러: 아트워크 있음/없음 모두 정사각형 이미지를 만들고, 생성 커버가
  제목/아티스트를 포함하는지.

### 수동

- 레코드를 **완전히 꺼낸 뒤**(고정/비고정 모두) ⌥+드래그 → 바탕화면에 **레코드 판**
  배치. 원본 재생/회전/열림 위치 불변.
- **완전히 열린 레코드**에서 ⌥+단발 클릭 → **열린 슬리브**가 기본 자리에 나타나고,
  0.18초 페이드 인 뒤 정적.
- 고정하지 않고 완전히 꺼낸 직후 ⌥+클릭/드래그 → 제스처 중 레코드가 올라가지 않고,
  끝난 뒤 1초 확인 창을 거쳐 닫히는지.
- 닫힌/덜 열린 상태에서 Option+클릭/드래그가 기존 동작을 바꾸지 않는지.
- ⌥+클릭만 했을 때 재생이 토글되지 않는지, 4~8pt 손떨림으로 사본이 생기지 않는지.
- 사본을 ⌥+드래그로 이동, 재실행 후 위치/형태/열림 상태 유지.
- 사본 중심을 상단 노치 삭제 존으로 끌어 삭제, 저장소에서도 제거.
- 바탕화면 사본에서 ⌥+클릭 → 열린 슬리브 → 닫힌 슬리브 → 레코드 판 → 열린 슬리브
  순환, 재실행 후 상태 유지.
- 커서를 사본 위에 올려둔 채 Option을 누르고 클릭/드래그해도 바로 동작하는지.
- 일반 클릭/드래그는 아무 동작도 하지 않는지(사본을 올리지 않음; 투명 여백은 삼킴;
  겹침/클릭 통과는 후속).
- 앱 창 아래에 가려지는지(데스크탑 레벨), 전체 화면 앱에서는 보이지 않는지.
- 여러 디스플레이: 다른 화면에 놓기, 화면 분리 후 재실행.
- 여러 스페이스: 스페이스를 2개 이상 만들고 전환해도 사본이 모든 스페이스의 같은
  위치에 보이는지.
- 앱을 완전히 종료했다가 재실행: 위치/형태/아트워크가 복원되는지.
- 주 디스플레이 변경, 디스플레이 분리/재연결: 저장된 화면이 있으면 유지, 없으면
  주 화면으로 클램프되는지.
- Music 꺼짐/트랙 없음/아트워크 없음 상태에서 복사·포장·복원.
- 앱 비활성화 → 활성화 시 사본 복귀.
- 메뉴 “바탕화면 레코드 정리” 확인/취소.
- 유휴 상태(사본만 떠 있음)에서 CPU가 0에 가까운지, Activity Monitor로 확인.

## 12. 후속 (Follow-ups)

아직 구현하지 않았으므로 이 문서의 확정 동작으로 읽으면 안 되는 항목:

- 시드 기반 회전(±3.5°): 사본마다 미세하게 기울여 겹침을 자연스럽게 만든다.
- 기본 겹침 배치: 새 사본이 기존 사본과 일부 겹치도록 두는 규칙.
- Option 없이 사본 영역 클릭이 Finder/데스크탑으로 통과하는 것.
- 겹친 사본 사이의 투명 여백 클릭 통과.
- 드래그 중 기울기와 놓을 때의 안착(lean/settle) 모션.
