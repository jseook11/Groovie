# 메뉴 바 · 상단 메뉴 UI 명세

상태: **v1 제안** (구현 전 검토용)
범위: 메뉴 바 상태 아이콘, 상태 메뉴 상단 헤더, 앱 아이콘
관련 문서: [design-spec.md](design-spec.md), [로고 시안](design/groovie-cream-transparent-v1.png)

---

## 1. 문제 정의

현재 상태 메뉴는 다음 두 항목으로 시작합니다.

```
Groovie
Music 재생 중 · 곡 제목
```

1. **메뉴 폭이 곡 제목에 종속된다.** 두 번째 항목이 `Music 재생 중 · <제목>` 형태라
   긴 제목에서는 메뉴 전체 폭이 그만큼 늘어나고, 트랙이 바뀔 때마다 폭이 흔들립니다.
2. **재생/일시정지 문구의 정보 가치가 낮다.** 이 앱의 상태 피드백은 이미 레코드가
   돌아가는지 멈춰 있는지로 전달됩니다. 메뉴에서 `재생 중`/`일시정지`를 텍스트로
   한 번 더 말할 이유가 없습니다.
3. **브랜드가 없다.** 메뉴 바 아이콘은 일반 SF Symbol(`opticaldisc`)이고,
   메뉴 상단도 앱 이름 텍스트 한 줄뿐입니다.
4. **정보 위계가 없다.** 앱 이름·연결 상태·곡 제목이 모두 같은 무게의 메뉴 항목으로
   나열되어, 정작 중요한 곡 정보가 가장 길고 눈에 띄지 않는 위치에 있습니다.

### 목표

- 트랙과 무관하게 **메뉴 폭을 고정**한다.
- 곡 제목은 고정 폭 안에서 **가로 마퀴(회전)** 로 읽는다.
- **재생/일시정지 텍스트를 제거**한다. 예외 상태(실행 중 아님·권한 필요)만 남긴다.
- 메뉴 바와 메뉴 상단에 **앱 로고를 적용**한다.

## 2. 설계 원칙

| 원칙 | 내용 |
| --- | --- |
| 고정 폭 | 메뉴 콘텐츠 폭은 트랙에 관계없이 항상 같다. |
| 정보 위계 | 곡 제목 > 아티스트 > 예외 상태 > 일반 메뉴 항목. |
| 상태는 침묵 | 재생/일시정지는 텍스트로 표시하지 않는다. 레코드가 말한다. |
| 예외만 말한다 | `Music 미실행`, `트랙 없음`, `권한 필요`처럼 사용자가 행동해야 하는 상태만 노출한다. |
| 두 가지 로고 | 메뉴 바는 단색 템플릿 심볼, 앱 아이콘은 크림 종이 배경. |
| 움직임은 절제 | 마퀴는 넘칠 때만, 느리게. 동작 줄이기에서는 멈춘다. |

## 3. 적용 표면

### 3.1 메뉴 바 심볼

SF Symbol을 제거하고 브랜드 마크로 교체합니다.

- **형태:** 가로로 긴 노치 하우징 + 아래로 반쯤 나온 레코드. 하나의 연결된 실루엣.
  - 노치 너비 `1.35D`, 높이 `0.22D`, 아래 모서리만 둥글게.
  - 레코드는 아래 반원만 보이고, 중심은 노치 하단 경계선 위.
  - 스핀들 구멍은 최소 1pt로 뚫어 실루엣에 리듬을 준다.
- **크기:** 광학 박스 `20 × 11 pt` (레코드 지름 약 13pt). 메뉴 바 행 높이 안에서
  수직 중앙 정렬. 1x/2x 표현을 모두 제공한다.
- **색:** `isTemplate = true` 단색. 시스템이 라이트/다크 메뉴 바에 맞춰 반전한다.
- **축소 보정:** 18pt 이하에서는 홈·셰인·종이 결을 모두 생략한다. 실루엣과
  스핀들 구멍만 남긴다. 1pt 선은 쓰지 않는다(안티앨리어싱으로 흐려짐).
- **상태 아이템:** 제목을 붙이지 않는다. `button.imagePosition = .imageOnly`,
  폭은 `variableLength`가 아닌 고정(약 24pt)으로 두어 메뉴 바가 흔들리지 않게 한다.
- **호버/클릭:** 시스템 기본 하이라이트를 그대로 사용한다. 커스텀 배경 없음.

> 대안으로 검토했던 "메뉴 바에 곡 제목을 직접 흘리기"는 채택하지 않습니다.
> 메뉴 바 공간은 여러 앱이 공유하고, 곡 정보는 메뉴를 열었을 때 읽는 편이
> macOS 관례에 맞습니다. 곡 제목은 3.3의 헤더가 담당합니다.

### 3.2 앱 아이콘

같은 작업에서 함께 적용하는 것을 권장합니다.

- **구성:** 크림 종이 배경(`#EBE0C9`) 위에 3.1의 마크를 광학 중앙 배치.
  - 마크는 아이콘 높이의 약 55%, 위쪽 여백을 조금 더 둔다.
  - 배경은 무광 종이. 강한 광택·베벨·드롭섀도 없음.
  - 러스트(`#B3543D`)는 레이블의 작은 포인트로만.
- **선정 시안:** [`app-icon-cream-v3.png`](design/app-icon-cream-v3.png) (1024×1024,
  Codex `image_gen` 생성). 상단이 평평하고 아래 모서리만 둥근 노치 하우징,
  크림 종이 배경, 아래 반원 레코드와 러스트 링 레이블.
  - 생성 프롬프트와 변형 기록은 [10. 생성 시안](#10-생성-시안) 참고.
  - 1차 시안(`v2`)은 하우징이 캡슐 형태라 폐기했다.
- **제작:** 선정 시안을 마스터로 사용한다. 1024 → 512 → 256 → 128 → 64 → 32 → 16px
  파생본을 만들되, 32px 이하에서는 홈·셰인을 생략한 단순화 버전을 별도로 만든다.
  래스터를 그대로 축소하면 16px에서 홈이 모아레로 뭉개지기 때문이다.
- **메뉴 바 심볼과의 관계:** 메뉴 바 심볼(3.1)은 이 래스터를 축소하지 않고
  벡터로 그린다. 20×11pt 템플릿에서는 AI 래스터보다 코드 드로잉이 선명하고,
  라이트/다크 반전도 `isTemplate`으로 자동 처리되기 때문이다.
- **패키징:** 선정 시안에 macOS 슈퍼타원 마스크를 적용해 모서리를 투명하게 만든 뒤
  `Resources/AppIcon.icns` 생성, `Contents/Resources`에 복사,
  `Info.plist`에 `CFBundleIconFile = AppIcon` 추가. `Scripts/build-app.sh`에서 처리.
- 참고: 기존 [로고 시안](design/groovie-cream-transparent-v1.png)은 형태·재질의
  기준으로만 사용한다(비정방형 구도, 큰 여백, 3D 렌더라 아이콘 원본으로는 부적합).

### 3.3 상태 메뉴 상단 헤더

기존 상단 두 항목(`Groovie`, `Music 재생 중 · 제목`)을 **커스텀 뷰 아이템 하나**로
교체합니다.

```
┌──────────────────────────────────────────────┐  252 pt
│  ▄▄▄▄▄▄▄▄                                     │
│   ◡◡◡◡    Blue in Green                      │  13 pt semibold
│           Miles Davis                        │  11 pt secondary
│           ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬     │  2 pt progress
├──────────────────────────────────────────────┤
│  ✓  활성화                                   │
│     데모 재생                                │
│     레코드 스킨                           ›  │
├──────────────────────────────────────────────┤
│     Music 연결 다시 시도                     │
│     Music 열기                               │
│     자동화 권한 설정…                        │
├──────────────────────────────────────────────┤
│     Groovie 종료                         │
└──────────────────────────────────────────────┘
```

#### 레이아웃

| 요소 | 값 |
| --- | --- |
| 콘텐츠 폭 | **252 pt** (메뉴 폭 고정) |
| 헤더 높이 | 56 pt (텍스트 블록은 수직 중앙) |
| 좌우 패딩 | 18 / 14 pt |
| 상하 패딩 | 10 / 9 pt |
| 로고 박스 | 22 × 22 pt (마크 20 × 11 pt, 수직 중앙) |
| 로고–텍스트 간격 | 10 pt |
| 제목 | 13 pt semibold, 1줄, 기본 라벨 색 |
| 아티스트 | 11 pt regular, 1줄, secondary |
| 진행 바 | 2 pt, 캡슐, 텍스트 폭 전체, 아티스트 아래 5 pt |
| 텍스트 영역 폭 | 252 − 18 − 22 − 10 − 14 = **188 pt** |

- 헤더 아이템은 **선택 불가**(하이라이트 없음)로 두고, 클릭 동작을 넣지 않는다.
  `isEnabled = false`여도 커스텀 뷰는 그려진다(단, 메뉴마다 뷰 인스턴스가 달라야 한다 — 5장 참고).
- 헤더는 로고를 포함한 **브랜드 블록**이므로 메뉴 항목 텍스트보다 오른쪽에서 시작한다.
  로고는 x=19, 제목은 x=50이며, 이 들여쓰기는 의도된 것이다.
- 다른 메뉴 항목(활성화·데모·스킨·연결 재시도·자동화·종료)의 자연 폭이 252 pt를
  넘지 않는지 확인한다. 넘으면 해당 문구를 줄여, 헤더 고정 폭이 실제 메뉴 폭을
  결정하도록 한다.
- 헤더 아래에 구분선 1개. 기존 `.separator()`를 그대로 사용한다.

#### 곡 제목 마퀴

| 항목 | 규칙 |
| --- | --- |
| 정지 조건 | 제목이 188 pt 안에 들어오면 움직이지 않는다. |
| 시작 | 메뉴가 열린 뒤 **0.7초** 대기 후 왼쪽으로 흐른다. |
| 속도 | **20 pt/s** (읽을 수 있는 상한) |
| 반복 | 제목 끝 + **28 pt 간격** 후 처음부터. 튕기지 않는다. |
| 가장자리 | 좌우 10 pt 페이드 마스크로 잘린 글자가 딱 끊기지 않게. |
| 종료 | 메뉴가 닫히면 즉시 정지하고 오프셋을 0으로 되돌린다. |
| 트랙 변경 | 텍스트를 교체하고 대기 상태부터 다시 시작한다. |
| 동작 줄이기 | 마퀴를 끄고 **가운데 생략(…)**, 툴팁에 전체 제목. |

- 아티스트는 마퀴하지 않고 **끝 생략**한다(제목보다 우선순위가 낮음).
- 제목이 비어 있으면 앱 이름 대신 `재생 중인 곡 없음`을 secondary로 표시한다.

#### 예외 상태

재생/일시정지 문구는 넣지 않습니다. 대신 다음 상태에서는 제목·아티스트·진행 바를
상태 문구로 대체합니다. 마퀴와 진행 바는 숨깁니다.

| 상태 | 헤더 표시 |
| --- | --- |
| `appNotRunning` | `Music이 실행 중이 아닙니다` |
| `noTrack` | `재생할 트랙이 없습니다` |
| `permissionDenied` | `자동화 권한이 필요합니다` · 작은 러스트 점 |
| `playing` / `paused` | 곡 제목 + 아티스트 (재생 상태 텍스트 없음) |

`paused`와 `playing`의 헤더는 **동일**합니다. 상태 차이는 레코드 오버레이가 전달합니다.

#### 진행 바 (권장)

- `position / duration`을 2 pt 캡슐로 표시한다.
- 메뉴가 열려 있는 동안에만 1초 간격으로 갱신한다. 이미 받은 스냅샷과 경과 시간으로
  로컬 보간하므로 **Music 추가 폴링은 없다**. 메뉴가 닫히면 타이머도 멈춘다.
- 목적: 없어진 재생/일시정지 텍스트 대신 **지금 어디쯤인지**라는 더 유용한 정보를 준다.
- 채택하지 않을 경우 헤더 높이를 48 pt로 줄이고 텍스트 블록만 남긴다.

## 4. 상태와 갱신 규칙

1. **트랙 변경** — 헤더 뷰의 텍스트만 교체한다. 메뉴를 다시 만들지 않는다.
   마퀴 오프셋을 0으로 리셋하고 대기 시간을 다시 준다.
2. **재생/일시정지 전환** — 헤더 텍스트를 바꾸지 않는다. 진행 바만 갱신.
3. **가용성 변화** — 예외 상태로/에서 전환될 때 헤더 내용을 교체한다.
   메뉴 구조(항목)는 그대로 두므로 재빌드는 필요 없다.
4. **구조 변경** — 활성화 토글, 스킨 변경처럼 항목 자체가 바뀔 때만 메뉴를 재빌드한다.
   메뉴가 열려 있는 동안 재빌드하지 않도록 `NSMenuDelegate.menuWillOpen/menuDidClose`로
   보류한다.
5. **메뉴 열림/닫힘** — 열릴 때 마퀴 타이머 시작, 닫힐 때 정지·리셋.

## 5. 구현 노트 (AppKit)

- **브랜드 마크** — 새 파일 `UI/BrandMark.swift`.
  `NSImage(size:flipped:drawingHandler:)`로 벡터 드로잉, `isTemplate = true`.
  메뉴 바용(20×11)과 아이콘용(큰 크기, 크림 배경) 두 진입점을 둔다.
- **상태 아이콘** — `AppDelegate.setUpStatusItem()`에서 SF Symbol 대신 `BrandMark.menuBar`
  사용. `button.imagePosition = .imageOnly`, 아이템 폭 고정.
- **메뉴 헤더** — 새 파일 `UI/MenuHeaderView.swift`.
  `NSMenuItem.view = MenuHeaderView(frame: NSRect(x: 0, y: 0, width: 252, height: 56))`.
  항목은 `isEnabled = false`로 두어 하이라이트·선택을 막는다.
- **메뉴마다 새 헤더 뷰** — `buildMenu()`에서 `MenuHeaderView()`를 새로 만들어 아이템에 붙인다.
  같은 뷰 인스턴스를 여러 메뉴 아이템에 재사용하면 AppKit이 뷰를 최신 메뉴로 옮기고,
  실제로 표시되는 메뉴의 아이템에는 뷰가 남지 않아 헤더가 **빈칸**으로 보인다.
  (구현 중 실제로 확인한 문제다.)
- **마퀴** — block 기반 `Timer(timeInterval: 1.0/60.0, repeats:)`를
  `RunLoop.main.add(..., forMode: .common)`에 등록해야 메뉴 추적(`NSEventTrackingRunLoopMode`)
  중에도 돈다. 경과 시간으로 오프셋을 계산하고, `masksToBounds`로 자른다.
- **측정** — 실제 렌더와 같은 `NSAttributedString` 속성으로 폭을 재서 188 pt와 비교한다.
  한글·이모지·결합 문자는 `size()` 결과를 그대로 사용한다.
- **접근성** — 헤더 뷰에 `setAccessibilityLabel("Groovie, <제목>, <아티스트>")`.
  마퀴는 VoiceOver에 영향을 주지 않는다.
- **앱 아이콘** — `Resources/AppIcon.iconset` → `iconutil -c icns`.
  `build-app.sh`에서 복사, `Info.plist`에 `CFBundleIconFile`.

## 6. 검수 기준

- [ ] 60자 이상 제목에서도 메뉴 폭이 252 pt로 유지된다(3개 트랙 비교).
- [ ] 짧은 제목에서는 마퀴가 전혀 움직이지 않는다.
- [ ] 메뉴를 열 때 레이아웃 점프가 없고, 헤더가 잘리지 않는다.
- [ ] `재생 중`/`일시정지` 텍스트가 메뉴 어디에도 없다.
- [ ] Music 미실행·트랙 없음·권한 필요 상태에서만 예외 문구가 나온다.
- [ ] 라이트/다크 메뉴 바 모두에서 심볼이 읽힌다. 16px에서도 노치+레코드 형태가 남는다.
- [ ] 동작 줄이기에서 마퀴가 꺼지고 가운데 생략 + 툴팁이 동작한다.
- [ ] VoiceOver가 헤더의 곡 정보를 한 번에 읽는다.
- [ ] 기존 메뉴 동작(활성화·데모·스킨·재시도·Music 열기·권한·종료)이 그대로 유지된다.

## 7. 검토한 대안

| 대안 | 판단 |
| --- | --- |
| 메뉴 바에 곡 제목을 직접 마퀴 표시 | 메뉴 바 공간을 과점하고 macOS 관례에서 벗어남. 곡 정보는 메뉴 헤더로. |
| 고정 폭 + 끝 생략만 (마퀴 없음) | 가장 단순하지만 긴 제목을 읽을 수 없음. 마퀴 채택. |
| 긴 제목을 여러 줄로 표시 | 메뉴 높이가 트랙마다 변해 더 산만함. 1줄 + 마퀴. |
| 글자를 실제로 회전(스핀) | 가독성 없음. "회전"은 가로 마퀴로 해석. |
| 헤더에 앨범 아트 표시 | 정보는 풍부하지만 로고 적용 요청과 어긋남. 로고 유지, 아트는 레코드 레이블이 담당. |
| 기존 렌더 PNG를 앱 아이콘으로 그대로 사용 | 비정방형·큰 여백·3D 렌더라 16/32px에서 뭉개짐. 정사각 크림 배경의 새 시안(v3)을 마스터로 채택. |

## 8. 결정이 필요한 항목 (권장안)

| 항목 | 권장 |
| --- | --- |
| 헤더 폭 | **252 pt** (280까지 허용) |
| 진행 바 포함 | **포함** — 없어진 재생 상태 텍스트의 빈자리를 더 유용한 정보로 채움 |
| 앱 아이콘 이번 작업에 포함 | **포함** — 로고 적용의 절반은 아이콘 |
| 메뉴 바 마크 크기 | **20 × 11 pt** 광학 박스 |
| 예외 상태의 러스트 점 | **포함** (권한 필요에만) |
| 헤더 클릭 동작 | **없음** — 메뉴 항목이 이미 명확함 |

## 9. 작업 순서 (구현 시)

1. `BrandMark` 벡터 드로잉 + 메뉴 바 상태 아이콘 교체.
2. `MenuHeaderView` 고정 폭 레이아웃(정적 텍스트) + 기존 두 항목 제거.
3. 마퀴 타이머·페이드 마스크·동작 줄이기 분기.
4. 진행 바 및 예외 상태.
5. 앱 아이콘 `.icns` 생성·패키징.
6. 16px 스크린샷, 긴/짧은 제목, 라이트/다크, VoiceOver 검수.

### v3 생성 프롬프트 (요약)

```text
Use case: logo-brand
Asset type: macOS app icon (rounded-square mask applied later in code)
Primary request: warm cream matte paper square with a centered black mark —
a wide horizontal camera-notch housing with the lower half of a black vinyl
record emerging beneath it, one connected silhouette. Record center exactly
on the housing bottom edge; only the lower semicircle visible. Small cream
paper label with a restrained rust printed ring and a punched spindle hole.
Style: refined analog product icon, subtle paper grain, delicate grooves.
Composition: square, dead-center, mark ≈55% of canvas height, generous margins.
Palette: #EBE0C9 background/label, #000000 housing, #0A0A0B vinyl, #B3543D accent.
Constraints: no text/letters/wordmark/numbers; no play button, tonearm, laptop,
notes, extra objects; no rounded tile edge, border, glossy bevel, rainbow
reflections, grime, heavy drop shadow, or watermark.
```

v3는 v2를 편집 대상으로 한 단일 변경이었다: 하우징 상단을 수평으로 평평하게,
상단 모서리를 각지게, 하단 모서리만 10% 반경으로 둥글게, 하우징 높이를 약간 줄임.
레코드·레이블·색·여백·조명은 그대로 유지했다.
